# Spring MVC Hello World

A small Java web application that demonstrates Spring MVC with XML configuration, JSP views, and Maven. The application is packaged as a WAR; it is not a Spring Boot application.

## Features

- Spring MVC request handling with an annotation-based controller.
- XML-based servlet and Spring application configuration.
- A JSP view rendered with JSTL and Bootstrap assets.
- An embedded Jetty Maven plugin for local development.
- A timestamped WAR artifact for each Maven build.

## Technology Stack

- Java 11
- Spring Web MVC 5.3.39
- Maven
- JSP and JSTL 1.2
- Embedded Jetty 10.0.26 for local development
- TestNG and JUnit for tests

## Prerequisites

- JDK 11 or later. The Maven compiler is configured with `--release 11`.
- Maven 3.6.3 or later.

Check that the tools are available:

```sh
java -version
mvn -version
```

## Run Locally

From the repository root, start the application with the embedded Jetty server:

```sh
mvn jetty:run
```

Jetty serves the application at the root context on port `9999`.

- Default greeting: <http://localhost:9999/hello>
- Greeting with a custom name: <http://localhost:9999/hello?name=Ada>

The `name` query parameter is optional. If it is omitted, the application displays `Hello World!`.

## Build

Run the full Maven lifecycle, including tests and WAR packaging:

```sh
mvn clean verify
```

The WAR is written under `target/`. Its filename follows this pattern:

```text
simple-maven-sprint-boot-example-<version>-<timestamp>.war
```

The timestamp uses the `yyyyMMdd-HHmmss` format. For example:

```text
simple-maven-sprint-boot-example-octobre-20261014-114542.war
```

The version is taken from the project version in `pom.xml`; the timestamp is generated by Maven at build time.

To compile and package without running the tests:

```sh
mvn -DskipTests package
```

## Tests

Run all tests with:

```sh
mvn test
```

The TestNG tests are grouped as `unit`, `integration`, and `functional`. Run an individual group with:

```sh
mvn -Dgroups=unit test
mvn -Dgroups=integration test
mvn -Dgroups=functional test
```

The current tests are sample assertions rather than end-to-end checks of the web application. Their random-value assertions can fail intermittently when the generated value is below the asserted lower bound.

## Request and View Flow

1. The `DispatcherServlet` receives requests, as configured in `src/main/webapp/WEB-INF/web.xml`.
2. Spring scans `com.agile611.hello` and registers `HelloController`.
3. A `GET /hello` request reaches the controller, which adds the supplied `name` (or `World`) to the model.
4. The MVC view resolver maps the returned view name to `/WEB-INF/views/hello.jsp`.
5. Static files under `/resources/` are served from the web application resources directory.

The root and MVC contexts are configured in `src/main/webapp/WEB-INF/appconfig-root.xml` and `src/main/webapp/WEB-INF/appconfig-mvc.xml`.

## Project Layout

```text
src/main/java/       Java application code
src/main/resources/  Application properties and Logback configuration
src/main/webapp/     Web resources, Spring XML configuration, and JSP views
src/test/java/       TestNG test classes
docker/              Legacy Dockerfile
target/              Maven build output (generated)
```
